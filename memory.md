## 3. Процедура выгрузки `.cf` → исходники (проверено, работает)

**Что НЕ выводит исходники:** чтение `.cf` как файла (бинарный контейнер) и попытки
распаковать без v8unpack бесполезны.

1. Создать/подготовить файловую ИБ, загрузив в неё конфигурацию из `.cf`:
   `1cv8.exe CREATEINFOBASE /F"..." /Template"...cf"` (эквивалент скилла `db-create -UseTemplate`).
   Здесь база `C:\1c_base\GK` уже существовала с загруженной конфигурацией.
2. Выгрузить конфигурацию в файлы (ключевой вызов):
   ```powershell
   $args = @('DESIGNER','/F','"C:\1c_base\GK"','/DumpConfigToFiles','"C:\project\0509\cfg_src"',
             '/DisableStartupDialogs','/DisableStartupMessages','/Out','"C:\project\0509\dump_log.txt"')
   Start-Process -FilePath $v8 -ArgumentList $args -NoNewWindow -Wait -PassThru
   ```
3. `ExitCode=0` ⇒ успех. Результат — дерево `cfg_src/` с `Configuration.xml` и каталогами
   объектов (Catalogs, CommonModules, Enums, Roles, ScheduledJobs, …).

**Критичный нюанс PowerShell:** аргументы `/F», `/Out», путь к каталогу должны быть
**отдельными элементами массива** со своими кавычками. Передача цельной строкой
(`& $v8 /DESIGNER /F"C:\1c_base\GK" ...`) ломает парсинг → «Неопределен режим запуска»
(exit 1). Рабочий вариант — `Start-Process -ArgumentList` как в скриптах скиллов
`db-dump-cf.ps1` / `db-load-cf.ps1`.

## 5. Ключевые факты о конфигурации (сводка)

- **Идентификация:** «1С:ГитКонвертер, ред. 1.0», версия **1.0.5.8**, поставщик «1С»
  (ООО «1С-Софт»), CC BY-SA 4.0, UUID `a8dd2e89-c043-4f61-ab58-dafb034cd4c1`.
- **Состав:** 14 общих модулей, 4 справочника, 2 перечисления, 2 регистра сведений,
  3 регламентных задания, 2 обработки, 1 отчёт, 3 роли. Подсистем, документов нет.
- **Ядро:** `CommonModules.КонвертацияХранилища` (~3 700 строк). Главная точка входа —
  регламентное задание; конвейер версий по состояниям; работа с Git через генерацию
  `.bat/.sh` команд; временные ИБ и отчёты для истории хранилища.
- **Очереди:** модуль `ОбработкаОчередей` пакетно обрабатывает версии (опция
  `ИспользоватьОчередиВыполнения`).
- **Формат выгрузки (проверено по коду):** дамп версии выполняется **всегда в XML 1С**
  (`DESIGNER /DumpConfigToFiles`); 1C:EDT — только опциональный шаг импорта
  (`ring edt workspace import`) по флагу `КонвертироватьВФорматEDT` (реквизит справочника
  «Хранилища конфигураций», по умолчанию выключен). Детали и строки кода — раздел 9
  файла анализа.
- **Временные файловые ИБ (проверено по коду, стр. 174–216 `modules-analysis.md`):**
  конвертация создаёт 2 вида временных файловых ИБ через `CREATEINFOBASE`:
  1. отчётная `<КаталогВыгрузкиВерсий>\report_db\` — для отчёта по версиям, удаляется сразу
     после загрузки версий (`УдалитьФайлы` в `ВыполнитьКонвертацию`);
  2. рабочая ИБ **на каждую версию** `<КаталогВыгрузкиВерсий>\<Код>\db\` — создаётся в
     `ПолучитьВерсиюВБазу`, наполняется `DESIGNER /ConfigurationRepositoryUpdateCfg -force -v`,
     затем из неё `DESIGNER /DumpConfigToFiles` в `...\dump\`. Добавляется в список баз
     (`CREATEINFOBASE ... /AddInList`).
  Удаляются каталоги версий (включая ИБ) **только** при включённой опции
  `ХранилищаКонфигураций.УдалятьВременныеДанныеВерсииПослеКоммита` (по умолчанию **Ложь**).
  Все ключевые процедуры/точки входа (с номерами строк) сведены в раздел 5.5 анализа.
- Подробный разбор — в [`modules-analysis.md`](modules-analysis.md).

## 6. Решения и состояние работы

- **Источник выгрузки:** по решению пользователя использована существующая база
  `C:\1c_base\GK`, а не новая чистая ИБ из `.cf`. Состав совпадает с логом загрузки
  конфигурации. ⚠ Если нужна 100% гарантия соответствия исходному `.cf` — пересоздать базу
  через `CREATEINFOBASE /Template`.
- **[2026-09-07 19:06] Серверные временные базы (задача «нет клиентской лицензии»):**
  реализован пул серверных временных ИБ через справочники `Кластеры` и `ВременныеБазы`
  (параметры MSSQL/PostgreSQL), режим «только занятие/освобождение» («создавать пустую ИБ»;
  без DROP/пересоздания, ibcmd в окружении отсутствует). Сделанное в `cfg_src`:
  - Метаданные (ранее): `Catalogs.ВременныеБазы`, `Catalogs.Кластеры` (реквизиты
    АдресСервера/ТипСУБД/СерверСУБД/ИмяПользователяСУБД/ПарольПользователяСУБД/
    ИмяПользователяКластера/ПарольПользователяКластера/ПрефиксИмениБазы/
    КоличествоВременныхБаз/ИспользоватьДляВременныхБаз/ЭталонВременнойБазы/Комментарий),
    `Enum.ТипыСУБД` (MSSQL/PostgreSQL), `Enum.СостоянияВременныхБаз`
    (Свободна/Занята/ТребуетПересоздания); на `ХранилищаКонфигураций` —
    `ИспользоватьСерверныеВременныеБазы` + `КластерВременныхБаз`; на `ВерсииХранилища` — `ВременнаяБаза`.
  - `Catalogs\ВременныеБазы\Ext\ManagerModule.bsl` (новый): `НайтиСвободную`, `Занять`,
    `Освободить` (не освобождает «ТребуетПересоздания»), `ПометитьПересоздание`.
  - `CommonModules.КонвертацияХранилища`: `ПолучитьКластерВременныхБаз`,
    `ПараметрыПодключенияККластеру`, `ПолучитьИмяПользователяИБ`, `СтрокаСозданияСервернойБазы`;
    `ПолучитьВерсиюВБазу` — серверная ветка (найти свободную → занять → `/S"..."` → обновить
    из хранилища; CREATEINFOBASE для предсозданной базы пула не выполняется), fallback на файловую;
    отчётная ИБ (`report_db`) в `ВыполнитьКонвертацию` — тоже через пул с занятием/освобождением;
    `ПолучитьПараметрыОбработкиВерсии`/`ВыгрузитьВерсию` — сохраняют серверную строку соединения
    из реквизита версии; `УдалитьФайлыВерсии`/`ПроверитьПолученныеВерсии` — освобождение базы.
  - Формы: `Кластеры` (ФормаЭлемента+ФормаСписка), `ВременныеБазы` (ФормаЭлемента+ФормаСписка),
    в `ХранилищаКонфигураций.ФормаЭлемента` добавлена группа «Серверные временные базы»
    (флаг + кластер). В `Элементе` проставлены PasswordMode для паролей и дефолты
    (`ПриСозданииНаСервере`: ТипСУБД=MSSQL, КоличествоВременныхБаз=5, ИспользоватьДляВременныхБаз=Истина;
    у ВременныеБазы Состояние=Свободна).
  - Валидация: cf-validate OK, form-validate по всем изменённым формам OK.
  - Для снятия `[support-guard]` (`support: capability-off`, конфигурация пришла из `.cf` поставщика)
    в корень проекта добавлен `.v8-project.json` с `editingAllowedCheck: "off"`.
  - **Не сделано (состояние проверки загрузки):**
    - **Реальные базы находятся не в `C:\1c_base\GK`, а на `E:\file_bases`** (расхождение с памятью):
      база ГитКонвертера — **`E:\file_bases\git_converter`**. Проверять программу загрузки
      (`db-load-xml`) по пути `C:\1c_base\GK` НЕЛЬЗЯ — его нет, падает с "information base not found".
    - Платформа в окружении — **`C:\Program Files\1cv8\8.3.27.2214\bin\1cv8.exe`** (не 2325).
    - Для отладки создан эталон исходников из базы: **`cfg_ref`** (`/DumpConfigToFiles` из `git_converter`),
      он загружается обратно успешно (ExitCode=0). `cfg_src` (с правками) — НЕ грузится.
    - **Найденные проблемы загрузки `cfg_src` (`-Format Hierarchical`, ExitCode=1):**
      1. `Catalogs\ВерсииХранилища.xml` — дублировался открывающий тег `<TabularSection>`
         (было 2 подряд). **Исправлено** (удалён лишний, теперь файл сбалансирован).
      2. Ошибка «Объект не найден - CatalogRef.ВременныеБазы» — `ВерсииХранилища.xml` ссылается
         на новый справочник `ВременныеБазы`, который в `Configuration.xml` стоял ПОСЛЕ
         `ВерсииХранилища`. Переставил `<Catalog>ВременныеБазы</Catalog>` перед
         `<Catalog>ВерсииХранилища</Catalog>` в `cfg_src\Configuration.xml`.
      3. Ошибка «Объект не найден - CatalogRef.Кластеры» — `ХранилищаКонфигураций.xml`
         (реквизит `КластерВременныхБаз`) ссылается на новый `Кластеры`.
      4. Гипотеза: ограничение Designer `LoadConfigFromFiles` — ссылка на **новый** объект из
         существующего в рамках одного прохода не резолвится (в `cfg_ref` cross-ссылки между
         существующими работают). Рекомендуемый обход — **двухфазная загрузка**:
         Фаза 1 = только новые объекты (справочники `ВременныеБазы`/`Кластеры`, перечисления
         `ТипыСУБД`/`СостоянияВременныхБаз`) без правок существующих; Фаза 2 = полный `cfg_src`.
      5. **Незавершено/нужна проверка:** тест «ref + новые объекты без правок существующих»
         (эталон + новые catalogs/enums только) дал ExitCode=1 с общей ошибкой
         «Ошибка преобразования данных XML» (по «чистому» Configuration.xml). Ранее test4
         (то же, но с «грязной» Configuration.xml через Set-Content) давал ExitCode=0 —
         расхождение требует проверки. Серия чистых тестов (cfg_tA/tB) прервана пользователем.
    - Чистка: в `E:\project\0509 git converter` остались отладочные каталоги `cfg_ref`,
      `cfg_phase1`, `cfg_probe`, `cfg_test*`/`cfg_t*` (часть уже удалена), логи `load_*.log`,
      `dump_ref.log`, `dump_probe.log` — можно удалять после завершения проверки.
- **Разбор временных ИБ (05.09.2026):** подтверждено, что в процессе конвертации создаются
  временные файловые ИБ (отчётная `report_db\` + рабочая на версию `<Код>\db\`). Результат —

## 7. Заметки/наблюдения на будущее

- Если в каталоге появится единичный файл ` C`, `dump_log.txt` "3 байта" или аномальные
  артефакты — это остатки ошибочного парсинга аргументов PowerShell при вызове 1cv8,
  можно удалять.
- Информация о «последней версии XML 1С = 1.0.5.8» (из `gk-migration-diagram.md`) согласуется
  с фактической версией конфигурации — полезно для справок о миграции в 1C:EDT
  (теперь подтверждено кодом: дамп всегда XML, EDT — опциональный импорт, раздел 9 анализа).
- При выключенной опции `УдалятьВременныеДанныеВерсииПослеКоммита` на диске накапливаются
  каталоги версий с временными ИБ (`<Код>\db\`) и дампами (`<Код>\dump\`) — главный источник
  роста занимаемого места. Для версий в состоянии `ВерсияПомещена` такие каталоги безопасно
  удалять вручную; временные базы попадают в список баз 1С (`/AddInList`), поэтому при частой
  конвертации список баз «мусорится».

# Расхождения вендорской документации и платформы 8.3.27.2214

Проверено на стенде **02.10.2026**, платформа `8.3.27.2214`, `ibcmd --version` → `8.3.27.2214`.
Метод: прямое обращение к `ibcmd` на временной файловой базе `%TEMP%\gk_check_ib` и на поднятом
автономном сервере `ibsrv.exe`. Каждое утверждение воспроизводится командами ниже.

**При расхождении доверять платформе.** Вендорский текст — источник намерений, но не контракт:
часть параметров он относит к группе целиком, тогда как платформа их не принимает.

## 1. `config export`: файлы пишутся только в пустой каталог

| Команда | Каталог назначения | Результат |
|---|---|---|
| `config export <каталог>` | пустой | ✅ успех |
| `config export <каталог>` | **непустой** | ❌ `Каталог … не пуст.` |
| `config export objects … --out=<каталог>` | **непустой** | ❌ `Каталог … не пуст.` |
| `config export info --out=<каталог>` | любой | ✅ |
| `config export --sync <каталог>` | с существующей выгрузкой | ✅ |

У `1cv8 /DumpConfigToFiles` такой проверки нет — файлы просто перезаписываются. Навык `db-dump-xml`
проверяет «каталог непуст» и отказывается с подсказкой; молча чистить каталог нельзя.

## 2. `config export info`: `--out` — это каталог, а не файл

Вендорский текст: «`--out=<file>` — Путь к файлу, в который будет записываться информация о конфигурации».
Платформа принимает **каталог** и сама кладёт туда `ConfigDumpInfo.xml`:

```
ibcmd infobase config export info --out=<каталог>            → [INFO] … успешно завершен
ibcmd infobase config export info --out=<каталог>\ConfigDumpInfo.xml
    → [ERROR] Каталог не обнаружен '<каталог>\ConfigDumpInfo.xml\ConfigDumpInfo.xml'
```

## 3. `Changes` — это `--sync`, а не `--base`

| Что нужно | Параметры платформы |
|---|---|
| Обновить существующую выгрузку на месте (аналог `1cv8 -update -force`) | `export <каталог> --sync --force` |
| Выгрузить **изменения в новый пустой каталог** | `export <каталог> --base=<ConfigDumpInfo.xml>` |

- `--base` требует **пустого** каталога назначения (на непустом — `Каталог … не пуст.`);
- `--base` и `--sync` **взаимоисключающи**: `Опции base и sync не могут быть использованы одновременно`;
- `--force` у экспорта означает «полная выгрузка, если версия формата выгрузки не совпадает с
  записанной в `ConfigDumpInfo.xml`» — то есть смысл тот же, что у `1cv8 -update -force`.

Первая реализация `db-dump-xml` ошибочно использовала `--base`; исправлено на `--sync --force`.

## 4. `config import`: параметры не у всей группы

Вендорский текст относит `--no-check`, `--archive`, `--base-dir` к группе `import` целиком. Фактически:

| Параметр | `import <каталог>` | `import files <файлы…>` | `import all-extensions <каталог>` |
|---|---|---|---|
| `--extension`, `--out` | ✅ | ✅ | ✅ |
| `--no-check` | ❌ `Ошибка разбора параметра` | ✅ | ✅ |
| `--archive` | ❌ `Ошибка разбора параметра` | ✅ | не проверялось |
| `--base-dir` | ❌ `Ошибка разбора параметра` | ✅ | не проверялось |

Проверено: `ibcmd infobase config import <каталог> --no-check` → `Ошибка разбора параметра: --no-check`.
Навык `db-load-xml` проверяет матрицу и отказывает с объяснением, а не пропускает флаг молча.

## 5. `eventlog` не принимает параметры подключения к базе

`ibcmd eventlog export <каталог журнала>` — читает **каталог журнала регистрации** (обычно
`<каталог данных сервера>\log-data`). Параметры `--data`, `--db-path` режим не принимает:

```
ibcmd eventlog export <log-data> --data=<каталог>
    → [ERROR] Ошибка разбора параметра: --data=…
```

Допустимы только `--pid` / `--remote` (работающий автономный сервер) и параметры самой выгрузки:
`--format` (`xml`/`json`), `--skip-root`, `--from`, `--to`, `--follow`, `--out`.

Выгрузка за период без событий **создаёт валидный файл** (скелет XML/JSON, ~95 байт), а не пустой:
признак «событий не было» — содержимое, а не размер.

## 6. `session` и `lock` — только работающий автономный сервер

```
ibcmd session list --db-path=<файловая база>  → [ERROR] Ошибка разбора параметра: --db-path=…
```

Режимы `session`/`lock` принимают **только** `--pid=<pid>` или `--remote=<url>`. Поведение:

| Ситуация | Результат |
|---|---|
| `session list` на работающем сервере без сеансов | код `0`, **пустой вывод** |
| `lock list` на работающем сервере | записи в формате `ключ : значение` (не таблица, как у `session list`) |
| `session info` с несуществующим uuid | код `0`, **пустой вывод** |
| `--pid` несуществующего процесса | `Процесс с указанным идентификатором не найден или недоступен` |

Пустой вывод при коде `0` навык `db-session` отличает от успеха: для `list` печатает
«активных сеансов нет», для `info` поднимает ошибку.

## 7. `extension create` требует `--name-prefix`

Вендорский текст описывает `--name` и `--name-prefix` без указания обязательности:

```
ibcmd infobase config extension create --name=X --purpose=patch  → «Не указано значение параметра: name-prefix»
```

`--name-prefix` фактически обязателен.

## 8. `1cv8 CREATEINFOBASE`: локаль задаётся внутри списка параметров

```
1cv8 CREATEINFOBASE File="..." /L en
    → Creation of infobase ("File="...";Locale = "ru_RU";)   ← /L молча проигнорирован
1cv8 CREATEINFOBASE File="...";Locale = "en";
    → Creation of infobase ("File="...";Locale = "en";)     ← принято
```

Отдельный ключ `/L` **не работает**; код локализации — часть строки параметров базы.

## 9. Режим `binary-data-storage` не описан в вендорском тексте

Обнаружен через `ibcmd help`: перечислен среди поддерживаемых режимов, но раздела 4.10 в
приложении нет. Не используется навыками; при необходимости — спрашивать `ibcmd help binary-data-storage`.

## 10. Автономный сервер: порты по умолчанию конфликтуют с кластером

`ibsrv.exe` на этой машине не поднимается с настройками по умолчанию: его `--direct-regport` по
умолчанию **1541** — тот же порт, что у менеджера кластера:

```
[FATAL] Адрес '0.0.0.0:1541' уже используется ('<путь к mngsrv.dll>')
```

Рабочий запуск на тестовой базе:

```
ibsrv.exe --db-path=<файловая база> --data=<каталог данных> \
          --http-port=8399 --direct-regport=8350 --debug-port=8351 --monitor-port=8352 --address=localhost
```

Про `-L` полей автономного сервера: `--http-port` (по умолчанию 8314), `--direct-regport` (1541),
`--ssh-port` (1543), `--debug-port` (1550), `--monitor-port` (1555).

| `Changes` = `--sync --force` | `db-dump-xml` |
| матрица параметров `import` | `db-load-xml` (отказ с объяснением) |

| `1cv8` локаль внутри списка параметров | `db-create` |
| порты `ibsrv` | `db-session` (описано в SKILL.md), стендовая заметка |

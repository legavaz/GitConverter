# ibcmd — исследование вендорской документации и доработка скиллов

**Дата исследования:** 02.10.2026 · **Платформа:** `C:\Program Files\1cv8\8.3.27.2214\bin` (`ibcmd --version` → `8.3.27.2214`)

## Зачем эта папка

Отдельного скилла `ibcmd` в проекте нет. `ibcmd` используется как **альтернативный движок** внутри 13 скиллов
семейства `db-*` / `epf-*` / `erf-*`: движок выбирается по имени исполняемого файла, переданному в
`-V8Path` (`ibcmd.exe` → движок `ibcmd`, иначе `1cv8`).

02.10.2026 изучена документация вендора по `ibcmd`, и выявлено расхождение между возможностями утилиты и
тем, что скиллы реально используют. Исследование зафиксировано здесь; **правки в скиллы пока не вносились**
(решение владельца — отложить, см. [ПЛАН-ДОРАБОТКИ.md](ПЛАН-ДОРАБОТКИ.md)).

## Главный вывод исследования

> **Ранее зафиксированное утверждение «ibcmd работает только с файловыми базами» — НЕВЕРНО.**
> Ограничение вендорское отсутствует: `ibcmd` управляет **автономным сервером** и поддерживает СУБД
> (`--dbms=MSSQLServer|PostgreSQL|IBMDB2|OracleDatabase`; не задан → файловая БД), а также подключение к
> работающему автономному серверу (`--pid` / `--remote`).

Ограничение «только файловая база» в 13 скиллах — **собственное решение проекта**, а не возможностей утилиты:
в offline-режиме `ibcmd` поднимает собственный автономный сервер прямо против СУБД, поэтому базу, которую
держит живой кластер `1С:Предприятие`, отдавать под второй движок нельзя.

Все базы проекта — кластерные серверные (`localhost\GitConv`, `localhost\task`), поэтому на текущий момент
создание второго движка на них не допускается.

## Как использовать этот материал

1. Прочитать [РАСХОЖДЕНИЯ-ДОКУМЕНТАЦИИ-И-ПЛАТФОРМЫ.md](РАСХОЖДЕНИЯ-ДОКУМЕНТАЦИИ-И-ПЛАТФОРМЫ.md) —
   это самая практичная часть: что документация врёт и на что опираться.
2. При сомнении сверяться с `ibcmd help <режим>` — он печатает контракт **установленной** платформы.
3. Помнить: каждый навык дублируется на PowerShell **и** Python — правки вносятся в обе реализации;
   общий блок helper-функций в `.py` копируется дословно из навыка-эталона
   (в группе `db-*` его держит одинаковым внешний `tests/skills/check-inline-drift.mjs`).

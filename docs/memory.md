## ИСПРАВЛЕНО: аутентификация хранилища для временных баз (22.09.2026)
- **Проблема:** команды работы с хранилищем (`ConfigurationRepositoryReport`, `ConfigurationRepositoryUpdateCfg`) подключались к хранилищу под пользователем **хранилища** (`ХранилищаКонфигураций.ИмяПользователяХранилища`). Из-за этого все временные базы шли под одним пользователем — конфликт «Пользователь существующей связи отличается от текущего», параллельная работа невозможна.
- **Решение:** подключаться под пользователем, указанным в **элементе временной базы** (`ноВременныеБазы.ИмяПользователяХранилища`/`ПарольПользователяХранилища`).
- **Код** (`CommonModules/КонвертацияХранилища/Ext/Module.bsl`):
  - новая процедура `УстановитьПользователяХранилищаВременнойБазы(РеквизитыБазы, Параметры)` (после `ПараметрыПодключенияКХранилищу`);
  - вызов после выбора серверной базы в `ВыполнитьКонвертацию` (отчёт по версиям) и в `ПолучитьВерсиюВБазу` (получение версии).

## 9. Открытый вопрос (нужно решение)

В конфигурации нет операции «привязка без изменения»: физическое подключение базы
к существующему хранилищу возможно только через `/ConfigurationRepositoryUpdateCfg`
(привязка + обновление конфигурации до версии) и выполняется при конвертации. Варианты:

1. **Оставить только логическую привязку** (рекомендую) — физическое подключение произойдёт
   при первой конвертации (каждая база под своим пользователем).
2. Выполнить `ConfigurationRepositoryUpdateCfg -force -v 251 -UpdateDBCfg` каждой базой
   под её пользователем (загрузит текущую конфигурацию хранилища).
3. Вручную указать целевую версию.

### 14.2. В сообщение добавлено количество метаданных коммита (27.09.2026)

## 16. Кнопка «Получить все версии и заполнить пользователей» (27.09.2026)

В форме элемента справочника «Хранилища конфигураций» добавлена команда **`ctmЗаполнитьВерсииИПользователей`**
(кнопка в командной панели). Что делает по нажатию:

1. Формирует отчёт по **всем отсутствующим** версиям хранилища тем же механизмом, что и конвейер
   (временная база — файловая или свободная из пула; `/ConfigurationRepositoryReport`; `/DumpResult`).
2. Записывает версии в справочник `ВерсииХранилища` (`ВерсииХранилища.ЗагрузитьВерсииИзОтчета`).
3. Собирает различные значения поля `ВерсииХранилища.Пользователь` по этому хранилищу и **предзаполняет**
   `РегистрСведений.ИнформацияПользователей`: по каждому логину без записи создаётся запись с `Имя = логин`
   и пустым `Email` (e-mail нужно заполнить вручную — без него коммиты не выполняются).

**Реализация:**
- `КонвертацияХранилища.ctmЗагрузитьВерсииХранилища(Хранилище)` (Экспорт) — п.1–2, возвращает `Успешно/Описание/ВерсийВсего`;
- `КонвертацияХранилища.ctmЗаполнитьПользователейХранилища(Хранилище)` (Экспорт) — п.3, возвращает число добавленных записей;
- форма: клиентская команда `ctmЗаполнитьВерсииИПользователей` + `…Завершение` + серверная функция `…НаСервере`;
- форма XML: команда `id=13` (заголовок «Получить все версии и заполнить пользователей»), кнопка `id=210`.

Загружено в базу частично (3 файла: модуль ядра, `Form.xml`, `Form/Module.bsl`), `/UpdateDBCfg` — успешно;
выгрузка базы совпадает с `cfg_src`.

**Замечание:** MCP-сессия 1С стартовала до загрузки и видит **старую** конфигурацию (динамическое обновление
действует на новые сеансы), поэтому проверить кнопку/методы из MCP-инструментов можно только после перезапуска

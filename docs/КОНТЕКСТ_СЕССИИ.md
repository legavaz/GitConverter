## 9. Открытый вопрос (нужно решение)

В конфигурации нет операции «привязка без изменения»: физическое подключение базы
к существующему хранилищу возможно только через `/ConfigurationRepositoryUpdateCfg`
(привязка + обновление конфигурации до версии) и выполняется при конвертации. Варианты:

1. **Оставить только логическую привязку** (рекомендую) — физическое подключение произойдёт
   при первой конвертации (каждая база под своим пользователем).
2. Выполнить `ConfigurationRepositoryUpdateCfg -force -v 251 -UpdateDBCfg` каждой базой
   под её пользователем (загрузит текущую конфигурацию хранилища).
3. Вручную указать целевую версию.

### 14.2. В сообщение добавлено количество метаданных коммита (27.09.2026)

## 19. Git-репозитории конвейера и VS Code: «dubious ownership» (27.09.2026)

**Симптом:** Git Graph / история git в VS Code не открываются для репозитория, созданного конвейером
(`E:\rep\erp25ExtDopFunkcional_git`). В консоли git — `fatal: detected dubious ownership in repository`.

**Причина:** репозиторий создаётся процессом **сервера 1С** (rphost, учётная запись `KOMPUTER\USR1CV8`),
поэтому владельцем `.git` является `USR1CV8`, а пользователь (`KOMPUTER\lega`) — другой. Git 2.35.2+
(у нас 2.54.0) отказывается работать с такими репозиториями без явного разрешения, и VS Code/Git Graph
(используют обычный `git`) показывают пустую историю.

**Решение (уже применено):** путь добавлен в глобальный `~/.gitconfig`, как и для прежних репозиториев:

```
git config --global --add safe.directory E:/rep/erp25ExtDopFunkcional_git
```

Текущий список: `task_git2`, `task_git_clean`, `task_git_clean2`, `task_git_file205`, `task_git_file210`,
`erp25ExtDopFunkcional_git`. После правки `git log`/`git status` в этом репозитории работают без
обходного `-c safe.directory` (проверено: 3 коммита, ветка `master`, дерево чистое).

**Важно:** каждый новый git-репозиторий, созданный конвейером (`ЛокальныйКаталогGit` в справочнике
«Хранилища конфигураций»), принадлежит `USR1CV8` и требует записи в `safe.directory`. По решению владельца
27.09.2026 включено **универсальное правило**:

```
git config --global --add safe.directory '*'
```

Проверено изолированным конфигом (только `safe.directory=*`): `git log`/`git status` в репозитории,
созданном сервером 1С, работают, а после удаления записи ошибка `dubious ownership` возвращается.
Итоговый список `safe.directory`: 6 явных путей + `*`. Новые репозитории конвейера открываются
в VS Code/Git Graph без дополнительных настроек.

**После правки:** в VS Code выполнить «Developer: Reload Window» — Git Graph пересканирует репозиторий.
Отдельно учтено: в настройках VS Code стоит `git.openRepositoryInParentFolders: "never"`, поэтому репозиторий
вне открытой папки не подхватывается автоматически — его нужно открыть как папку (или добавить в рабочую
область).

### 20.1. Продолжение разбора: перебор коммитов, кэш модулей, пустые коммиты (27.09.2026, 17:00–17:35)

**Второй дефект (блокировал коммиты).** `ВыполнитьКоммиты` перебирает версии, начиная от `&Код` (код элемента = 3),
и **выходит с `Возврат` на первой необработанной версии** (модуль, стр. 762): при `ПерваяВерсия = 3740` версии
4…3739 не обрабатываются, поэтому цепочка вставала на версии 4 и коммиты не выполнялись никогда.
Локализовано временной трассировкой (событие ЖР `КХ.Отладка.Коммиты`):
«Версия=1…3 (Версия помещена) → Версия=4 (пусто) → `Выход 762`».
Правка: нижняя граница перебора = `ПерваяВерсия − 1`. Первая попытка вставки оказалась **внутри**
`Если ТипЗнч(РеквизитыХранилища.Код) <> Тип("Число")` (для числового кода блок не выполнялся) — исправлено,
блок вынесен наружу. Трассировка после отладки удалена.

**Важный вывод про динамическое обновление.** Правки модуля, загруженные с `/UpdateDBCfg`
(«Конфигурация обновлена динамически»), **не применяются к уже запущенному сеансу/rphost**: начинает работать
только новый сеанс/новое фоновое задание, а прямые вызовы из текущего сеанса идут по старому скомпилированному
коду. Именно поэтому предыдущие правки выглядели «не работающими» — после `restart_1c_session` код стал новым
(в трассировке появился `НачальныйКод`).

**Третий дефект — причина найдена и устранена.** Коммиты 3740–3746 получались **пустыми**
(`On branch master / nothing to commit`), а версии при этом помечались «Версия помещена» с хешем `fd55317`
(коммит версии 3). Причина — **форматирование номера версии с разделителем групп**: в команде оказывалось
`/ConfigurationRepositoryDumpCfg "…\ext_3 747.cfe" -v3 747`, то есть конфигуратор получал `-v3` и каждый раз
выгружал **версию 3**, содержимое совпадало с уже закоммиченным → «nothing to commit».
Исправление: `Версия = Формат(Параметры.ВерсияХранилища, "ЧДЦ=; ЧГ=0");` (без разделителей).

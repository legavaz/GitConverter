## 9. Открытый вопрос (нужно решение)

В конфигурации нет операции «привязка без изменения»: физическое подключение базы
к существующему хранилищу возможно только через `/ConfigurationRepositoryUpdateCfg`
(привязка + обновление конфигурации до версии) и выполняется при конвертации. Варианты:

1. **Оставить только логическую привязку** (рекомендую) — физическое подключение произойдёт
   при первой конвертации (каждая база под своим пользователем).
2. Выполнить `ConfigurationRepositoryUpdateCfg -force -v 251 -UpdateDBCfg` каждой базой
   под её пользователем (загрузит текущую конфигурацию хранилища).
3. Вручную указать целевую версию.

- `ФоновыеЗадания.Выполнить` из MCP-сессии вешает вызов — длительные операции запускать

  пока указатель не догонит актуальную; при пустом `ВерсияВGit` ставить на последнюю помещённую.
- Запись `ПоследняяВерсия` и `ВерсияВGit` выполнять отдельными `Записать()`.

## 13. Дефект версии 200 — обнулено и очищено (27.09.2026, 13:07)

**Что было.** Запись версии 200 после перезапуска цикла имела `Состояние = МетаданныеЗагружены` и пустой `Хеш`,
хотя коммит `3719107` фактически есть в рабочем репозитории `E:\rep\task_git_file210` (первый коммит истории).
Таймлайн по регистру `СостоянияВерсии`: 10:44:57 — `ВерсияПомещена` (успех), 10:45:27 — сброс в пустое
состояние и повторный цикл, остановившийся на `МетаданныеЗагружены` (10:45:45). Коммит больше не выполняется,
т.к. `ВыполнитьКоммиты` отбирает версии только с `Код > ВерсияВGit` (сейчас 210).

**Что сделано (обнулить + очистить).**
- `Состояние = ПустаяСсылка`, `КаталогВременныхФайлов = ""` (указывал на уже удалённый `task_temp_file_safe\200\`),
  `ВыгрузкаИзменений = Ложь`; `Хеш` и `Источник` очищены автоматически обработчиком `ПередЗаписью` объекта.
  Регистр `СостоянияВерсии` получил штатную запись с пустым состоянием (13:07:04).
- Удалены файлы-остатки версии 200 в каталоге выгрузки `E:\rep\task_temp_file210`:
  `git_command_200.bat`, `git_comment_200.txt`, `git_log_ver_200.txt` (472,8 КБ).
- Версии 201–210 не затронуты: `ВерсияПомещена` с корректными хешами (10 из 10).

**Важное следствие (нужно решение).** `ВыполнитьКонвертацию` отбирает версии с пустым состоянием в диапазоне
`ПерваяВерсия..ПоследняяВерсия` (200–210) → при следующем запуске конвейер снова возьмёт версию 200, заново
скачает её из хранилища и остановится на `МетаданныеЗагружены` (коммит невозможен: `Код ≤ ВерсияВGit`),
т.е. дефект воспроизведётся. Варианты:
1. вывести 200 из диапазона: `ХранилищаКонфигураций.ПерваяВерсия = 201`;
2. вернуть согласованность: `Состояние = ВерсияПомещена`, `Хеш = 371910788738ecff4d78124360dbb96f09d5f2f7`;
3. полный перезапуск диапазона: очистить `ВерсияВGit` + состояния 200–210 и пересоздать репозиторий.

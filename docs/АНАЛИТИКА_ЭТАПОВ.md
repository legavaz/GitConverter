## 1. Как считается

Для каждой версии записи регистра сортируются по периоду; время пребывания в состоянии = разница между текущей записью
и следующей записью **этой же версии**. Интервал относится к состоянию из текущей записи (то есть фактически измеряется
длительность работы, начавшейся при входе в состояние). Терминальное состояние (`ВерсияПомещена`) и стартовое
(`ПустаяСсылка`) интервала не имеют — они отражают простой, а не работу.

Готовый код для повторного расчёта (запускается на сервере, например через MCP-инструмент выполнения кода):
запрос по `РегистрСведений.СостоянияВерсии` с полями `Период, ВерсияХранилища, ВерсияХранилища.Владелец, Состояние`,
сортировка `ПО Хранилище, Версия, Период`, затем накопление в `Соответствие` по ключу «хранилище|состояние»
(кол-во, сумма секунд, максимум) и вывод с `Формат(Сумма/3600, "ЧДЦ=1")`.

**Оговорки:** а) счётчики включают повторные переходы (перезапуски, ретраи, сбросы состояний при отладке);
б) периодичность регистра — секунда, поэтому переходы в одну и ту же секунду схлопываются; в) состояния
`ПустаяСсылка` и `ВерсияПомещена` — простой (ожидание запуска / уже закоммичено), а не рабочее время.

## 3. Как пересчитать заново

1. Запустить приведённый выше запрос по `РегистрСведений.СостоянияВерсии` (данные накапливаются, чистка не требуется).
2. Сгруппировать интервалы по (хранилище, состояние) — получить кол-во/сумму/среднее/максимум.
3. Сравнить с этим снимком: рост среднего времени «Начало коммита»/«Выгрузка версии» сигнализирует о деградации
   (например, из-за роста объёма конфигурации или узкого места дисковой подсистемы).

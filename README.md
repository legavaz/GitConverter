# GitConverter — конвертация хранилища 1С в Git

> Проект: `E:\project\0509 git converter` · ветка `lega-master` · репозиторий https://github.com/legavaz/GitConverter.git
> Обновлено: 27.09.2026

## Что это

Конфигурация 1С **«1С:ГитКонвертер, ред. 1.0»** (версия 1.0.5.8) + внешний движок **gitsync**:
перенос истории хранилища разработки 1С в Git-репозиторий (гибрид: пул временных баз ГитКонвертера
+ движок gitsync). Ядро — общий модуль `cfg_src/gitConverter/CommonModules/КонвертацияХранилища`.

### Шаг 1 (выполняется ПЕРВЫМ). Прописать пользователей хранилища

Пока пользователи не прописаны, автором коммита станет **логин в хранилище 1С**, а e-mail — `anonimous@localhost`
(так и вышло при первом прогоне 200–210: `danilin`, `Администратор`, `ponomarev`). Если же выключен флаг
хранилища `РазрешитьПомещатьАнонимноЕслиНеНайденПользователь` — коммиты **не выполняются вовсе** (молча, без ошибки в ЖР).

Заполняется регистр сведений **`Информация пользователей`**
(«Все функции» → Регистры сведений → Информация пользователей; форм у регистра нет — записи вводятся набором записей):

| Поле | Роль | Пример |
|---|---|---|
| `Хранилище` (измерение) | элемент справочника «Хранилища конфигураций» | `E:\rep\task` |
| `Пользователь` (измерение) | логин пользователя **в хранилище 1С** — как в отчёте по версиям | `danilin` |
| `Имя` (ресурс) | отображаемое имя автора коммита в Git | `Данилин В.И.` |
| `Email` (ресурс) | e-mail автора коммита в Git (без него коммит не пройдёт) | `danilin@company.ru` |

Строка заводится на **каждую** учётную запись хранилища, встречающуюся в истории версий. Поддерживаются
записи-фолбэки: с пустым `Хранилище` (общая для всех хранилищ) и с пустым `Пользователем` (значение по умолчанию).
Значения подставляются в коммит как `GIT_AUTHOR_NAME` / `GIT_AUTHOR_EMAIL` (и `GIT_COMMITTER_*`); пустой e-mail
заменяется на `anonimous@localhost`.

### Шаг 2. Заполнить реквизиты хранилища

Адрес, `КаталогВыгрузкиВерсий`, `ЛокальныйКаталогGit`, `ИмяВетки`, диапазон версий (`ПерваяВерсия` / `ПоследняяВерсия`),
режим работы (файловый или серверные временные базы), флаги `ВыполнятьКоммиты`, `ВыгружатьИзменения`,
`РазрешитьПомещатьАнонимноЕслиНеНайденПользователь`.

### Шаг 3. Создать git-репозиторий

Кнопка «Создать репозиторий Git» в форме элемента хранилища: выполняет `git init`, локальные настройки
(`core.quotepath`, `core.autocrlf`, `diff.renames` и др.), создаёт `.gitignore` и `.gitattributes`.

### Шаг 4. Подготовить пул временных баз (для серверного режима)

Справочники «Кластеры» и «Временные базы»: базы создаются и привязываются к хранилищу, каждой назначается
пользователь хранилища; `МаксимальноеКоличествоПодготавливаемыхВерсий` не может превышать число баз хранилища.

### Шаг 5. Включить регламентное задание

«Регламентное задание» хранилища (расписание, например, каждую минуту) — оно запускает конвейер:
получение версии → выгрузка → загрузка метаданных → коммит.

> ⚠️ **Перед повторным прогоном диапазона обязательно очищать `КаталогВыгрузкиВерсий`** — конвейер
> переиспользует уже существующие `git_command_N.bat` / `git_comment_N.txt`, и коммиты уйдут со старым текстом сообщения.
